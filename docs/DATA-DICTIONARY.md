# 数据定义 供应商主数据台账

## 输入列契约

| 列名 | 别名 | 类型 | 可空 | 说明 |
|---|---|---|---|---|
| `supplier_id` | 供应商编码、供应商号 | 字符串 | 否 | 来源系统内的记录号，保形不去零 |
| `supplier_no` | 供应商编号、编码 | 字符串 | 否 | 集团编码，前导零保留 |
| `name` | 名称、供应商名称 | 字符串 | 否 | 原始名称，至少 4 字 |
| `tax_id` | 税号、纳税人识别号 | 字符串 | 是 | 空串表示确实没有税号，哨兵另记标记 |
| `city` | 城市 | 字符串 | 是 | 用于城市不一致降级判定 |
| `bank_account` | 开户行账号 | 字符串 | 是 | 保形，仅作证据 |
| `erp_source` | 来源系统 | 字符串 | 是 | ERP-A 到 ERP-D |
| `ref_master_id` | 主档号 | 字符串 | 是 | 声明本记录归属的主档，需通过引用核验 |
| `ytd_amount` | 本年累计 | 十进制 | 是 | 单位元，两位小数，Decimal 存储 |
| `last_update` | 更新时间 | 日期 | 是 | 来源系统日期，不参与计算 |
| `entity_status` | 主体状态、状态 | 字符串 | 是 | 存续/注销/吊销/停业等；缺列视为未提供 |
| `open_balance` | 未结余额、余额 | 十进制 | 是 | 单位元，两位小数；缺列或空值按 0.00 |

`entity_status` 与 `open_balance` 是可选列：旧文件的列契约不变，缺列时全部记为
未提供 / 0.00，不影响既有批次的对账。它们只在编码复用与接替判定中使用：
`entity_status` 进入“旧主体是否已注销”的证据，`open_balance` 进入余额归属。

## 批次标识

- `run_id` 由输入摘要（按文件名排序的 sha256 拼接）与规则版本共同取摘要，
  因此同一批文件重跑得到同一个批次，规则版本升级后同输入会生成新批次。
- 运行清单同时保留每个文件的 sha256、字节数、编码与分段数。

## 空值与哨兵

- `null` 与空串：字段确实没有值，例如空税号表示该供应商未登记税号。
- 哨兵：`-`、`--`、`n/a`、`na`、`null`、`none`、`未知`、`无`、`空`、`/`，
  只在 `app/config.py` 的 `SENTINEL_VALUES` 定义一次。
- 税号哨兵记为 `F_TAX_SENTINEL`，金额哨兵记为 `F_AMOUNT_SENTINEL` 并落 0.00；
  两者都不进入税号比对，但会出现在导出的标记列里。

## 数值

- 金额与合计一律 `Decimal`，最小刻度 0.01，对外 JSON 与 CSV 用字符串。
- 簇内分摊：按成员金额比例，取整到分后用最大余额法补齐，合计恒等于簇金额。
- 比例与得分保留 6 位小数，权重 0.55 与 0.45 定义在 `app/config.py`。

## 时间

- 采集时间与复核时间一律 UTC 存储（`YYYY-MM-DDTHH:MM:SSZ`），页面显示 `+08:00`。
- 复核查询时间窗为左闭右开 `[since, until)`：`since <= decided_at < until`。

## 名称归一规则

| 编号 | 规则 | 示例 |
|---|---|---|
| N01 | 全角转半角 | （北京） → (北京) |
| N02 | 括号统一 | 〔北京〕 → (北京) |
| N03 | 去空白 | 鼎新 科技 → 鼎新科技 |
| N04 | 去法律后缀 | 有限公司 / 股份有限公司 / 集团 / 控股 / 公司 |
| N05 | 去地名标记 | 北京鼎新科技 / 鼎新科技(北京) → 鼎新科技 |
| N06 | 拉丁小写 | ABC → abc |
| N07 | 去标点 | 残留标点与空括号 |

行业词（物流、贸易、建材、化工等）不剥离，避免把不同主体并到一起。

## 相似度与分档

- bigram Dice = 2 × |A∩B| / (|A| + |B|)，A、B 为归一名的相邻两字集合。
- 编辑比率取 `difflib.SequenceMatcher(None, a, b, autojunk=False).ratio()`。
- 得分 = 0.55 × Dice + 0.45 × 比率，量化到 6 位。
- 分档：得分 ≥ 0.92 自动合并；0.80 ≤ 得分 < 0.92 人工复核；其余拒绝。
- 判定优先级：编码复用（拒绝） > 税号冲突（拒绝） > 税号相同（自动） > 城市不同（复核） > 得分分档。

## 编码复用与主体接替

同一 `supplier_no` 下出现两个不同 `supplier_id`，且税号不同或一侧缺失，即为
编码复用；税号完全相同的两条视为同一主体改名/补录，仍走普通合并。

| 情形 | 判定 | 旧主体 | 新主体 | 余额 |
|---|---|---|---|---|
| 税号相同 | `S_SAME_SUBJECT`，非复用 | 继续合并 | 继续合并 | 随主体 |
| 旧主体注销 + 名称一致 | `S_SUCCESSOR_CONFIRMED` 接替 | 退役 | 正式接替 | 结转新主体 |
| 旧主体注销 + 接替标记词 | `S_SUCCESSOR_CONFIRMED` 接替 | 退役 | 正式接替 | 结转新主体 |
| 名称一致但旧主体存续 | `S_SUCCESSOR_CANDIDATE` 疑似 | 保留可结算 | 待核验账户 | 留旧主体 |
| 无名称、无状态、无标记 | `S_NEW_SEPARATE` 另行启用 | 已注销则退役，否则保留 | 待核验账户 | 留旧主体 |

- 接替证据三项：名称一致、旧主体已注销/吊销/停业、名称或来源中出现
  `接替/承继/继受/受让/承接/并入/吸收合并`。证据 ≥2 才判接替，人工确认也须 ≥2。
- 编码复用的候选对判 `P_CODE_REUSE`（拒绝），普通复核不能对其下“合并”。
- 案件号 `SC-<集团编码>`，与批次无关；同一编码有多个新主体时追加新主体编号
  `SC-<编码>-<记录号>`。已批准/已发布的案件在重算时保留结论。

## 正式主数据版本

- 一次发布生成一个整版本（`master_versions.version` 单调递增），上一版整版写入
  `master_snapshots` 后标 `superseded`，不删除、不逐行覆盖。
- 余额只在编码复用切换时移动一次；重跑同一批先按 `(supplier_no, tax_id)` 认领
  已发布主体，不会把源数据余额重复累加。
- 台账分录按主体一条：退役且余额为 0 的不再产生应付；另行启用的新主体标
  `pending_account`，分录说明“暂缓付款”；保留余额的旧主体继续产生应付。
- 计划摘要 `payload_sha256` 覆盖案件结论、主体与台账；发布请求必须与当前摘要
  及 `expected_prior_version` 一致，否则分别报 `S_PAYLOAD_DRIFT` / `S_STALE_MASTER`。
- 回执 `receipt_id` 由批次与计划摘要决定；同一批已有成功回执时，摘要与旧版本都
  对得上才回放原回执，任一不符分别报 `S_PAYLOAD_DRIFT` / `S_RECEIPT_CONFLICT`。
- 发布在事务内再核对一次最新版本与已存在回执，两个请求同时提交也只有一个落库。

## 主体与代表元

- 并查集合并顺序无关，根取字典序较小的供应商号。
- 代表元 = 簇内税号最小者；无税号时取供应商号最小者。
- 簇编号按 (税号, 代表号) 升序分配。
- 簇内出现两个以上非空税号记 `CLUSTER_CONFLICT`，该簇不参与自动合并。

## 去重键与空态

- 去重键为 `supplier_id`；同键同值剔除并记 `Q_DUP_ID_SAME`，同键不同值进冲突表。
- 空态三态：仅表头 `header_only`、全空行 `blank_rows`、无数据行 `no_row`，
  三者在文件诊断里分别给出，不合并成同一个成功结论。
